Why Kepler

A browser that keeps its receipts.

Most browsers ask you to trust them. Kepler is built so you don't have to — the guarantees are enforced by the engine, not by a privacy policy.

01

Sealed tabs

Every origin gets its own sandboxed process with its own cookie jar, cache and storage partition. A tracker on one site is a stranger on the next.

02

Fingerprint flattening

Canvas, audio, fonts, timezone and device metrics are normalised to a shared profile, so a million Kepler users look like the same user.

03

Egress ledger

A live, filterable log of every outbound connection the browser makes — including its own. If Kepler phones home, you'll see the row.

04

Reproducible builds

The binary you download hashes to the same digest as the one you build from source. Same commit, same bytes, no exceptions.

05

Devtools that don't lie

Unminified stack traces, request timing without the rounding fudge, and a protocol console you can script from the terminal.

06

Orbit relays

Optional multi-hop routing through volunteer relays, switchable per profile, so a hardened session is one keystroke away.

For developers

Scriptable from the first keystroke.

Kepler exposes the same protocol its own devtools use. Drive it from a shell script, a test runner, or a language server — no headless fork, no patched build.

  • A stable CDP-compatible socket on a port you choose.
  • Profiles as plain directories you can commit, diff and throw away.
  • Extensions run in WASM with a capability manifest you approve line by line.
  • Headless and headed share one binary and one config file.
// drive a hardened session from node import { connect } from "kepler/protocol"; const kep = await connect({ port: 9422 }); const tab = await kep.newTab({ profile: "throwaway", relays: 3, fingerprint: "flat" }); await tab.goto("https://example.dev"); const ledger = await tab.egress(); // every byte that left the machine console.table(ledger.requests); await tab.burn();

Under the hood

Rust where it counts.

Parsers, the network stack, the sandbox broker and the storage partitioner are all memory-safe Rust. The classes of bug that produce most browser CVEs simply aren't expressible there.

  • No unsafe outside 400 audited, documented lines.
  • Every parser is fuzzed continuously in CI against a shared corpus.
  • The release manifest is signed and served by a 300-line Rust binary.
// server/src/releases.rs — the manifest Kepler serves pub struct Release { pub version: String, pub platform: Platform, pub arch: Arch, pub sha256: Option<String>, pub available: bool, } impl Release { pub fn is_downloadable(&self) -> bool { self.available && self.sha256.is_some() } }

Trust, then verify

Don't take our word for it.

Every release ships with a detached signature and a build attestation. Three commands and you know the binary on your disk is the one in the public log.

keplerctl verify ./kepler-0.9.0-linux-x86_64.tar.zst
keplerctl attest --commit HEAD --reproduce
cargo run -p kepler-releases -- --serve 8080

Questions

The short answers.

Is Kepler a fork of an existing browser?
The rendering layer started from an existing open-source engine; the network stack, sandbox broker, storage partitioner and extension runtime are new and written in Rust. The divergence is documented commit by commit in the docs.
Does Kepler collect anything at all?
No. There is no analytics SDK, no crash pinging, no "anonymous usage" toggle that defaults to on. Crash reports exist but are files on your disk that you choose to attach to an issue.
Will my extensions work?
Extensions using the standard WebExtensions surface generally work. Anything requesting broad host permissions has to declare them in a capability manifest that you approve per-permission rather than all at once.
What does "reproducible" actually buy me?
It means a compromised build server can't hand you a different binary than everyone else without it being immediately visible. Anyone can rebuild the release and compare digests.
Is the beta safe to use as a daily driver?
It's stable enough that the team uses it daily, but the extension API and the profile format may still change before 1.0. Pin a version if you're scripting against it.
